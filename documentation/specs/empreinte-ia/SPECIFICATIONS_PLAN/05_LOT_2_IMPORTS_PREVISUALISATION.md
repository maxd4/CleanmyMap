# Prompt Codex : Lot 2/3, imports réels, prévisualisation et qualité

> **Statut documentaire : PLAN.** **Type : LOT XL / réécriture de la partie import du premier ancien prompt.** Cette spécification décrit le périmètre et les preuves restant à compléter; le code d’import du lot 2 est déjà publié. Le détail des fixtures fournisseur est fourni dans [02](./02_SOURCES_ET_FIXTURES_API.md). Les exports personnels de conversations et les décisions transversales du mode rapide restent gouvernés par [24](./24_ARBITRAGES_PREUVES_ET_PRIORITES.md); les exports de conversations non vérifiés demeurent PLAN/UNSUPPORTED.

**État vérifié le 22 novembre 2026 sur le `main` publié :** l’interface d’import, les parseurs pris en charge, l’API/RPC et les corrections d’identité sont dans le runtime publié. Les preuves PostgreSQL atomiques/RLS et E2E authentifiées restent bloquées avant les tests métier dans les workflows éphémères référencés par [24](./24_ARBITRAGES_PREUVES_ET_PRIORITES.md). Ne pas relancer le lot comme une création initiale.

```text
LOT 2/3 : Import de consommation IA multi-fournisseurs, aperçu puis confirmation.

OBJECTIF
Permettre d'importer des relevés CSV, JSON, JSONL et factures PDF textuelles dans « Mon empreinte IA », sans clé API ni stockage brut. Normaliser la sémantique propre à chaque fournisseur, puis consommer le même calculateur et le même stockage privé que le lot 1. Prendre aussi en compte les utilisateurs de chatbots grand public, sans les assimiler à des comptes API d'organisation.

JALON 1 : PARSEURS ET TESTS DE CONFORMITÉ
- Parseur OpenAI organization/usage/completions JSON avec buckets, input comprenant cached/cache-write, sorties multimodales, model null, has_more/next_page et dates Unix UTC. Fixture dérivée de la documentation officielle : input=1000, cache_read=400, cache_write=100, uncached=500, output=500, requêtes=5 ; total logique=1500, pas de double somme.
- Parseur Anthropic Analytics 2026 /v1/organizations/analytics/usage, distinct du legacy usage_report. Champs usage.uncached_input_tokens, usage.cache_creation.ephemeral_1h_input_tokens et ephemeral_5m_input_tokens, cache_read_input_tokens, output_tokens, requests, data_refreshed_at. Fixture de conformité : input=4 699 800, output=891 000, total=5 590 800, demandes=4210. Implémenter le legacy séparément uniquement si son format est prouvé.
- Parseur Gemini GenerateContentResponse.usageMetadata : total=prompt+candidates+toolUsePrompt+thoughts ; cache inclus dans prompt. Fixture synthétique 231+242+0+524=997, dont cache=50. Parseur Codex rollout JSONL : réutiliser les règles de compteurs cumulatifs et resets des scripts/data/ existants, extraire uniquement métriques, jamais transcript. Les formats réellement pris en charge sont recensés dans la fiche CURRENT de `/learn/empreinte-ia`; ne pas traiter cette liste de fixtures de PLAN comme une preuve supplémentaire.
- Exports individuels ChatGPT et Claude : leur import n’est pas livré. Leur structure doit être qualifiée par fixture représentative avant de coder des adaptateurs dédiés. Toute extraction future restera locale et ne présentera jamais activité visible ou longueurs comme tokens fournisseur exacts. Les arbitrages et preuves d’ouverture sont dans [24](./24_ARBITRAGES_PREUVES_ET_PRIORITES.md).
- CSV OpenAI/OpenRouter : mapper les colonnes vérifiées, sinon mapping guidé explicite avec validation ; pas de schéma inventé. PDF textuel : extraire en local et seulement les tokens/coûts effectivement identifiables ; une facture seulement monétaire conserve le coût, tokens/kWh/CO2e=null. Refuser PDF scannés/chiffrés et ne pas faire d'OCR ni d'IA externe.

JALON 2 : SÉCURITÉ ET PRÉVISUALISATION
- Traiter les fichiers dans le navigateur et en mémoire, avec parsing incrémental JSONL. Plafonds documentés : CSV/JSON 10 Mo et 20 000 lignes, JSONL 50 Mo et 250 000 lignes, PDF 5 Mo et 20 pages. Dépendance PDF légère, lazy-loaded uniquement si requise ; aucune donnée brute transmise à l'API.
- Onglet Importer : glisser-déposer, fichier choisi, détection format/version, aperçu fournisseur, modèle, compte/scope pseudonymisé, période, catégories de tokens, coût/devise, source, couverture des pages, nombres valides/rejetés, champs manquants, chevauchements et doublons. États explicites de rejet, partiel et prêt à confirmer ; confirmation utilisateur avant écriture.
- Pour les exports de conversation : aperçu de l'activité visible et de sa couverture, sans afficher inutilement les contenus textuels ni les mettre en logs, dans la télémétrie ou dans l'API ; les fichiers contenant des pièces jointes et les structures non reconnues n'autorisent aucune inférence de tokens cachés. La compatibilité d'un format non fixé reste PLAN/UNSUPPORTED.
- Empreinte normalisée owner-scoped ; identités stables des buckets révisables et suppression des duplications exactes. Pour scopes imbriqués, événements inclus dans des buckets, mêmes périodes et vues agrégées concurrentes : signaler conflit et exiger exclusion/choix, ne pas additionner automatiquement. Une estimation rapide du même utilisateur sur la même période doit pouvoir être exclue/remplacée, sans addition automatique à l'historique importé. Un bucket recouvrant deux mois sans détail de ventilation est hors agrégat mensuel.

JALON 3 : CONFIRMATION ET DOCUMENTATION
- Envoyer exclusivement des lignes normalisées/validées au service existant du lot 1. Confirmation multi-lignes ATOMIC dans la couche PostgreSQL ou RPC owner-scoped, pas de boucle HTTP partiellement validée ; idempotence après timeout et import concurrent, relecture des résultats enregistrés.
- Sans compte, calcul/aperçu temporaire autorisé mais aucun enregistrement ; connexion requise uniquement pour Confirmer. Aucune demande de clé fournisseur, aucun upload brut ni logs contenant prompts, factures ou identifiants personnels.
- Actualiser la fiche de page, la méthodologie d'import, la sécurité, RGPD, provenance, tableaux de formats effectivement supportés et versions de fixtures ; distinguer CURRENT, PLAN et formats non vérifiés.

VALIDATION
Exécuter les fixtures exactes OpenAI, Anthropic, Gemini et Codex ; cache, reasoning, multimodal, pagination tronquée, data_refreshed_at, model null, formats legacy, CSV échappé/BOM, PDF coût seul, PDF non textuel, taille excessive, erreur de décodage, doublons et collisions scopes. Ajouter fixtures représentatives anonymisées ChatGPT/Claude et tests de rejet des versions non reconnues, absence de contenu brut persistant, limite du traitement local, réparation d'un historique partiel et conflit avec l'estimation rapide. Tests de confirmation atomique, réimport, deux comptes Clerk, preuve PostgreSQL RLS en lane éphémère, E2E navigateur d'import puis suppression ; typecheck/lint, couverture Web ciblée et documentation CURRENT.

STOP CONDITION
Les formats réellement compatibles génèrent un aperçu puis un usage traçable, au niveau de preuve exact de la source. Les totaux ne doublent pas, les factures sans tokens ne créent aucune émission, les historiques visibles ne deviennent pas des tokens fournisseur, aucun secret ou brut n'est stocké et les imports refusés/partiels sont explicitement justifiés. Un format sans fixture probante peut rester non supporté sans bloquer les formats validés.
```
